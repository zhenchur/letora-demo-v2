# Поля ввода Леторы

В демке шесть обязательных полей, обязательное согласие на обработку персональных данных и необязательная подписка. Кнопка «Проверить поля» проверяет их вместе. Результат относится к локальной валидации стенда. При переносе в продукт состав полей, обязательность и серверные ошибки определяются сценарием формы.

[Макет формы](https://www.figma.com/design/j1cOxgS2tGUfkq1AeQwrEH/?node-id=2034-8069) · [Кит полей](https://www.figma.com/design/j1cOxgS2tGUfkq1AeQwrEH/?node-id=1382-2664)

## Какие правила подключать

| Сценарий | Поля и правила |
| --- | --- |
| Вход по почте | Почта и существующий пароль обязательны. Почта проходит проверку формата. Для пароля достаточно непустого значения. Использовать `autocomplete="current-password"` для пароля и `username` для почты как идентификатора аккаунта. |
| Регистрация | Почта, создаваемый пароль и его повтор. Подпись «Пароль» может оставаться такой же, как при входе. Для создаваемого значения применяются проверка нового пароля и `autocomplete="new-password"`. Повтор сравнивается с создаваемым паролем. Имя, телефон и согласие подключаются по требованиям экрана. Подписка остаётся отдельной и необязательной. |
| Восстановление по почте | На шаге запроса проверяется почта. На шаге установки проверяются новый пароль и его повтор. |
| Смена пароля | Надёжность проверяется у нового пароля. Повтор сверяется с ним. Если сценарий запрашивает текущий пароль, в клиентской форме проверяется его заполненность. |
| Профиль, оформление заказа, контактная форма | Для почты и российского телефона действуют те же проверки формата. Состав и обязательность контактов определяются задачей конкретного экрана. |

Совмещённая демка сравнивает повтор с «Новым паролем», а если он пуст, с полем «Пароль». Это позволяет проверить повтор при разных наборах заполненных полей. Финальная проверка стенда требует заполнить оба пароля. В отдельных формах у повтора должен быть один явный источник сравнения.

## Когда показывать ошибки

| Действие | Ожидаемое состояние |
| --- | --- |
| Открыть форму | Пустые поля показывают подпись в строке. У обязательных полей есть звёздочка и нативный `required`. |
| Войти в поле | Предыдущая ошибка поля скрывается. Появляется верхняя подпись, линия остаётся индиго. |
| Ввести значение | Телефон сразу форматируется. Сообщения о формате, надёжности и совпадении выводятся после выхода из компонента. |
| Выйти из поля | Для непустого значения запускается проверка по типу поля. Если пользователь стёр весь ввод, поле возвращается к исходному виду без ошибки. Переход на крестик или глаз считается движением внутри компонента. |
| Нажать «Проверить поля» или Enter в текстовом поле | Проверяются актуальные значения всех подключённых полей и обязательное согласие. Пустые обязательные поля получают сообщения. Фокус остаётся на элементе, с которого запустили проверку. Итог сообщается через `role="status"`. |
| Изменить значение после проверки | Итоговый статус убирается при вводе, очистке или изменении чекбокса. |

Верхний слот поля зарезервирован под подпись или ошибку. Под итоговый статус зарезервированы две строки, ошибка согласия находится в промежутке над чекбоксами. При замене сообщений проверьте, что текст помещается на узкой ширине и соседние поля сохраняют положение.

## Формат и тексты

| Поле | Условие | Сообщение |
| --- | --- | --- |
| Адрес электронной почты | Проверяется значение после обрезки внешних пробелов. Нужны части до и после одного `@`, точка в доменной части и минимум два символа после последней точки. Пробелы внутри считаются ошибкой. | «Некорректный адрес». При общей проверке пустого поля — «Введите адрес электронной почты». |
| Номер телефона | Российский формат с десятью национальными цифрами. | «Введите номер телефона» для пустого обязательного поля. Остальные сообщения перечислены ниже. |
| Имя | Свободный текст. При общей проверке после удаления внешних пробелов должен остаться хотя бы один символ. | «Введите имя». |
| Пароль при входе | Требуется непустое значение. | «Введите пароль». |
| Новый пароль | Непустое значение проверяется простой эвристикой. | «Пароль ненадёжный». При общей проверке пустого поля — «Введите новый пароль». |
| Повтор пароля | Точное совпадение с исходным значением, включая регистр и пробелы. Если исходное значение изменилось, сравнение повторяется при выходе из повтора или при общей проверке. | «Пароли не совпадают». При общей проверке пустого поля — «Повторите пароль». |
| Согласие | Для прохождения общей проверки обязательный чекбокс должен быть отмечен. Его изменение сбрасывает ошибку. | «Подтвердите согласие на обработку персональных данных». |

### Российский телефон

- Маска `+7 (___) ___-__-__` появляется в строке при фокусе. Каретка ставится после `+7 (`. Незанятые позиции видны приглушённым цветом, а при выходе скрываются. Один префикс считается пустым полем.
- Вставка `+7 (900) 123-45-67`, `79001234567`, `89001234567` или `9001234567` даёт один формат `+7 (900) 123-45-67`. В строке из десяти цифр первая `7` или `8` остаётся частью номера.
- При наборе и вставке сохраняются цифры и допустимые разделители. Вставка без цифр сохраняет выделение и значение. В середине номера Backspace и Delete работают по цифрам через разделители. Каретка остаётся у места правки.
- Неполный номер получает «Введите номер полностью». Значение с другим международным кодом или лишними цифрами остаётся видимым до исправления. Сообщения соответственно «Введите российский номер с кодом +7» и «Проверьте количество цифр». Ошибочная комбинация знаков, например повторный плюс, получает «Введите номер цифрами».


### Проверка нового пароля

Для анализа используется копия строки без внешних пробелов и в нижнем регистре. Пароль и его повтор сравниваются в исходном виде. Демка показывает «Пароль ненадёжный» в следующих случаях.

- Меньше восьми Unicode-кодовых точек.
- Распространённая основа вроде `qwerty`, `password` или `пароль`, в том числе с цифрами и знаками в конце.
- Цифровая последовательность вроде `12345678` или `87654321`.
- Точный повтор шаблона длиной от одного до четырёх символов, например `11111111` или `abcdabcd`.

Эвристика демонстрирует состояние ошибки. Требования к создаваемому паролю в продукте задаются серверной политикой.


## Очистка, видимость и оформление

- Крестик появляется при возвращении в поле, из которого пользователь ранее вышел с корректным значением. Нажатие очищает поле, убирает крестик и возвращает фокус в строку. При ручном стирании последнего символа крестик также скрывается. Для управляемого поля обработчик `onClear` обновляет значение формы.
- Глаз переключает видимость и в активном, и в неактивном поле. При нажатии указателем сохраняется уже установленный фокус и по возможности восстанавливается выделение. При работе с клавиатуры глаз и крестик получают отдельный фокус.
- Используйте нативные поля с доступными именами, подходящим `autocomplete` и `required`. Декоративная маска и дубль подписи скрываются от экранного диктора. При ошибке поле получает `aria-invalid` и ссылку на сообщение через `aria-describedby`. Если добавляете внешний текст подсказки, объедините его идентификатор с идентификатором ошибки внутри компонента.
- Декоративная подпись и остаток маски скрываются при браузерном автозаполнении. Включите вставку и автозаполнение в приёмку целевых форм, особенно со сторонним менеджером паролей.
- Верхняя подпись использует reveal из основного проекта. Подъём 8 px, поворот 3°, длительность 400 мс. Подпись в пустом поле использует посимвольный hover из проекта. В режиме `prefers-reduced-motion` эти анимации отключаются.
- У чекбоксов текст статичен. Внутри контура 10×10 px на hover появляется центрированный терракотовый квадрат 4×4 px. У отмеченного чекбокса контур прозрачен и виден квадрат 8×8 px. Полная строка доступна для нажатия. Клавиша Space переключает чекбокс, клавиатурный фокус виден.

## Приёмка перед подключением

| Проверка | Ожидаемый результат |
| --- | --- |
| Ввести `anna@example`, уйти, вернуться, стереть весь ввод и снова уйти | Ошибка появляется только при первом выходе. После стирания возвращается исходное пустое поле. |
| Вставить российский номер тремя способами, затем отредактировать середину | Видимый формат совпадает. Удаляются нужные цифры, каретка остаётся возле правки. |
| Вставить номер с кодом `+44` или с лишними цифрами | Строка остаётся видимой. Сообщение появляется при выходе. |
| Ввести `qwerty123` в «Пароль» и «Новый пароль» | Существующий пароль проходит проверку заполненности. Новый получает «Пароль ненадёжный». |
| Ввести несовпадающий повтор, исправить его, затем изменить новый пароль | На следующей общей проверке повтор сверяется с актуальным значением. |
| Вернуться в корректно заполненное поле, нажать крестик. Переключить глаз мышью и клавиатурой | Крестик появляется при возврате и исчезает после очистки. Глаз сохраняет строку пароля. Выход на внутреннюю кнопку сохраняет активность компонента. |
| Проверить пустую форму, затем заполнить всё обязательное и оставить подписку выключенной | Сначала видны ошибки шести полей и согласия. После заполнения — «Все поля заполнены корректно.». Положение полей и кнопки сохраняется. |
| Повторить на узкой ширине, с клавиатурой, автозаполнением и reduced motion | Подписи, значения и ошибки читаются. Все действия доступны. |
